ColorPro — live editor
======================

Causes corrected
----------------
The 45 ms trailing preview timer restarted on every value change, so continuous
dragging postponed all rendering. At native zoom it also rendered the entire
photograph, then encoded PNG in the worker and decoded it in the GUI thread.
Enter was a toggle with no release handling and was intercepted in numeric input.
Atomic parameter saves performed fsync/readback in the GUI thread and were only
scheduled when the delayed preview started. There was no async write ordering.

Persistence
-----------
Every edit schedules parameter autosave independently of pixel completion.
One background writer plus one newest pending snapshot bounds the queue. Immutable
captures include source identity, base hash, all four tools, undo/redo and view.
Only the latest matching acknowledgement marks the controls saved. Navigation and
close wait asynchronously for the last write, including input made during a write.
Failure keeps the editor open and retains the edits for retry. A return to the
current frame cancels pending navigation. Atomic JSON replacement remains unchanged.
The timed autosave writes only editor metadata. From 1.9.0, leaving a changed
frame or Ctrl+S commits the full-size result once, as in RetushPro. The image
commit point is tracked separately from saved metadata; a report warning never
marks committed pixels dirty again. Unchanged navigation and repeated Save do
not render or encode the image. A failed image write keeps the current editor.
Result revisions recover a committed worker result if the queue was not written.

New results go into ColorPro beside each source or inside a selected parent
directory; an empty custom destination falls back to each source. Existing
ColorPro directories are reused. Editing keeps each result's existing folder
and format. Destination preferences apply to new processing. The _СС suffix is
preserved, and processing the same source again reuses its verified owned result.
The parameters panel opens automatically with processed photos, including their
first edit. Manually hiding it is remembered; photos without results do not start
an editor. On reopening comparison, saved controls and history resume automatically.
The regular image loader already supported saved parameters; its preview work is
now bounded and does not render a complete export merely to open a small preview.

Preview and comparison
----------------------
From 1.10.1, the per-photo V39 report is removed from the comparison workspace.
Recorded processing decisions remain available internally for state recovery.

Reset to original is a separate undoable action for the active photo. It lazily
decodes the original InputItem (including ZIP members) off the GUI thread, keeps
the immutable V39 base, and resets all manual tools. A source-base marker travels
with snapshots, undo/redo, metadata and committed results; 4-field legacy snapshots
still read unchanged. Source mode uses original pixels for preview, histogram,
pickers, automatic tools and full export. Failed decoding leaves prior edits intact.
Navigation/close wait for loading and the existing save barrier. Reset never writes
the source or immediately exports a duplicate; unchanged repeat resets are no-ops.

From 1.9.1, drag and idle use the same display-resolution input. The previous
640 px drag proxy and 120 ms refinement caused visible blur/sharpness jumps.
The visible crop is now taken from native pixels and downsampled only to its
physical display size (including device pixel ratio), never enlarged from 640 px.
At 100% and above it uses native pixels. The previous sharp frame remains visible
until the new one is ready. Releasing a slider does not trigger another render.

One worker and one newest request prevent a backlog. Cropping/resizing is cached
per viewport and performed off the GUI thread; parameter changes reuse that input.
Pan/zoom/resize invalidate old geometry, checked between pixel operations and HSL
chunks. RGB lookup uses OpenCV's integer LUT with the same verified channel tables
as export, checked byte-for-byte against the original operator. QImage owns its
RGB bytes across threads; QPixmap is created only in the GUI thread. No PNG round
trip per edit. An unchanged LUT stage is reused for HSL-only adjustments. Verified
tables and the lookup backend are warmed during background session loading.
Downsampling is for display only; native crops and full-size export retain the
unchanged CC2014 RGB8 formulas. Autosave is independent of preview completion.

The existing common zoom/center synchronizes both panes. Labels now explicitly
offer 1 photo / 2 photos, with the divider retained; the mode is persisted.
Enter shows the source on key press and the result on release, ignores repeat,
resets on focus/window loss, and never captures Enter in text/numeric fields.
Custom key assignments remain supported. No render, disk write or timer is
invoked by hold comparison. RetushPro's hold/release and navigation behavior was
used as a read-only reference; its image-saving implementation was not copied.

Validation
----------
Tests cover continuous slider frames, exact native crop/export agreement, all
parameter groups, blocked disk writes with latest-wins close, quick navigation,
disk failure/retry, restart recovery, hold/repeat/keypad/custom keys/focus loss,
input fields, synchronized geometry and persisted mode. Release receipts include
measured 12 MP Qt5/Qt6 interaction, unchanged V39 inference, installer migration,
offline repair and both update channels. Qt5 on a modern host is not an actual
Windows 7 OS test. Measured latency depends on hardware and viewport size.
