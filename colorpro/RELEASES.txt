ColorPro: выпуск и обновления
===========================

Репозиторий: https://github.com/babkanomer13-dotcom/colorcorrection
Выпуски:    https://github.com/babkanomer13-dotcom/colorcorrection/releases
Теги приложения: colorpro-vMAJOR.MINOR.PATCH. Другие теги приложение игнорирует.

Windows 10/11 x64 (CUDA + CPU) и Windows 7 SP1 x64 (CPU) — разные каналы.
Обновление не требует GitHub CLI, логина или токена на компьютере пользователя.
TLS-проверка обязательна, включая перенаправления на GitHub CDN.
Подтверждаются SHA-256 манифеста и каждого файла по метаданным GitHub Releases.
Проверка повторяется перед запуском установщика. Это проверка целостности, не
цифровая подпись издателя. Установщики пока не имеют Authenticode-подписи.

При запуске установленного приложения — проверка не чаще суток; отключается
на странице «Обновления». Файлы скачиваются только по нажатию; установка — по второму
нажатию. Проверки и загрузка вне UI-потока. Ошибка сети не блокирует обработку.
Прерванная загрузка возобновляется, если сервер поддерживает HTTP Range.
Начиная с 1.3.0 обычное обновление компактное: включает только изменённые
файлы относительно всех поддерживаемых базовых сборок. Модель и библиотеки
не скачиваются повторно. Пакет совместим с автообновлением 1.1.0–1.2.1.
С 1.3.1 первая установка и обновление строго разделены:
Offline.exe — один полный офлайн-файл, включает Python, библиотеки и модель.
Setup.exe — только небольшой пакет изменений для установленного приложения.
Ни один из них не скачивает компоненты и не запускает другой установщик.
Полный Offline.exe при повторном запуске сравнивает SHA-256 и пропускает
совпадающие файлы. Восстанавливает только отсутствующие или изменённые.
Повреждённый runtime блокирует компактное обновление ДО записи файлов:
в этом случае для восстановления нужен Offline.exe, а не повторная загрузка
компонентов в обычном обновлении. Настройки и результаты не затрагиваются.
Версии до 1.3.0 использовали EXE + BIN; они оставлены неизменными как базовый
комплект. Их нельзя удалять: уже опубликованный 1.3.0 использует эти файлы.

Во время обработки/превью установка недоступна. Именованный mutex защищает
живые процессы (включая другую копию приложения). Процессы не уничтожаются.
Установка идёт поверх того же каталога, сохраняет QSettings и папки фотографий.
После установки приложение запускается с ярлыка. При отмене до установки
действующая версия не меняется. Лог установки: LOCALAPPDATA/ColorPro/updates.
Не прерывайте работающий установщик и не выключайте ПК во время установки.
Сборка 1.0.0 не умеет обновляться: переход на 1.1.0 выполняется установщиком вручную.

Разработчику
------------
Правило пользователя: каждый готовый выпуск приложения публикуется через
встроенное обновление. Локальные установщики — резерв, не окончательная выдача.
После публикации проверять обнаружение нового выпуска в обоих каналах.
Самостоятельно устанавливать обновление на ПК пользователя или закрывать его
работающие программы нельзя: установка остаётся действием пользователя.

1. Изменить colorpro/__init__.py и ProductVersion в colorpro/build/setup.iss.
2. Выполнить pytest colorpro/tests; отдельно проверить совместимость Python 3.8.
   GitHub Actions проверяет updater на Python 3.8 и 3.12 без доступа к весам/фото.
3. Собрать две платформы через build/stage.py и ColorPro.spec.
   Сборка требует сохранённой V39; учебные датасеты и optimizer не включаются.
   Win7 требует отдельного проверенного окружения и downlevel CRT; не собирать
   Win7 из современных библиотек и не утверждать тест на Win7 без целевого ПК.
   Создать компактный план через build/compact.py, сравнив dist со ВСЕМИ
   поддерживаемыми базами. Изменение DLL/весов требует отдельной миграции runtime,
   а не выдачи полного комплекта за обычное обновление. Компилировать setup.iss
   с /DCompactRoot=<план>. Сохранить <platform>-compact.json рядом с EXE для
   publish_release.py. Для полного файла создать план compact.py --offline,
   компилировать с /DFullRoot=<план>. DiskSpanning=no. Не пересобирать baseline.
4. Прогнать build/verify_frozen.py, чистую офлайн-установку одним EXE, повторный
   запуск полного EXE с проверкой неизменных mtime компонентов, обновление старых
   версий без сети/без загрузки runtime, отказ при повреждении, удаление и Win7 static audit.
   Проверить полное совпадение результата V39, JPEG100 4:4:4 и сохранность исходников.
5. Сохранить только продуктовые исходники в коммите. Никаких приватных фото,
   конфигураций, токенов, train-state или путей из отчётов в публичном репозитории.
6. python -m colorpro.build.publish_release --artifacts <папка> создаёт manifest/SHA.
7. Добавить release-notes.txt. После тестов и push конкретного коммита:
   python -m colorpro.build.publish_release --artifacts <папка> --publish
       --commit <40-char SHA> --notes <release-notes.txt>
   Публикация сначала draft, затем проверка ВСЕХ удалённых digest и только потом
   снятие draft. Если upload прерван — продолжить gh release upload недостающих
   файлов, затем --verify-draft. Никогда не перезаписывать опубликованный релиз.
8. Убедиться, что latest_release видит выпуск в обоих каналах, а установленная
   актуальная версия не предлагает ни повторную установку, ни откат.
